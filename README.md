# amoCrm Buffer Worker

Автономный скрипт для перемещения сделок из этапа **«Буфер»** в целевой этап в amoCRM.
Запускается по расписанию через Cron.

## Структура проекта

```
amocrm-buffer-worker/
├── config.py        # Настройки (ID этапов, лимит, данные интеграции)
├── auth.py          # Модуль авторизации OAuth2 (автообновление токена)
├── worker.py        # Основной скрипт (запускается по Cron)
├── setup_auth.py    # Первичная авторизация (получение токенов)
├── tokens.json      # Файл с токенами (создаётся setup_auth.py, НЕ КОММИТИТЬ)
├── .gitignore
└── README.md
```

## Подготовка

### 1. Регистрация интеграции в amoCRM

1. **amoCRM → Амемаркет → Создать интеграцию → Внешняя интеграция**
2. Скопируйте **Integration ID (Client ID)**, **Secret key** и **Redirect URL**
3. Заполните эти поля в `config.py`

### 2. Сбор ID воронки и этапов

- **pipeline_id** — ID воронки (берётся из адресной строки при открытии воронки)
- **buffer_status_id** — ID этапа «Буфер»
- **target_status_id** — ID этапа, куда перемещать сделки

Заполните их в `config.py`.

### 3. Установка зависимостей

```bash
pip install requests
```

## Первичная авторизация

```bash
python3 setup_auth.py
```

Скрипт выдаст ссылку. Перейдите по ней, авторизуйтесь в amoCRM,
после редиректа скопируйте код из URL и вставьте в консоль.
Токены будут сохранены в `tokens.json`.

## Ручной запуск (тестирование)

```bash
python3 worker.py
```

## Настройка Cron

```bash
# Каждые 30 минут
*/30 * * * * cd /home/www/amocrm-buffer-worker && python3 worker.py >> worker.log 2>&1

# Раз в день в 9:00
0 9 * * * cd /home/www/amocrm-buffer-worker && python3 worker.py >> worker.log 2>&1
```

## Как это работает

```
Cron → worker.py
         ├── 1. Проверка/обновление Access Token (auth.py)
         ├── 2. GET /api/v4/leads (фильтр: этап «Буфер», сортировка: по дате asc)
         ├── 3. Если буфер пуст → выход
         └── 4. PATCH /api/v4/leads → перемещение найденных сделок в целевой этап
```

## Безопасность

- `tokens.json` содержит секретные токены — **не коммитьте его в Git**
- Файл добавлен в `.gitignore`
- Рекомендуется ограничить доступ к папке через `.htaccess` или chmod
